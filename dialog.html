dialog

Messages, dialogs, and attachments: the data model for LLM conversations stored as notebooks

A dialog keeps an LLM conversation in a Jupyter notebook. You can mix Markdown notes, runnable code with its outputs, and prompts with their replies. You can view, edit, diff, and version-control the conversation with notebook tools.

The format comes from Solveit, where people have used dialogs for their daily work for a couple of years. aidialog makes that format available to other tools. You can read and build dialogs, edit individual messages, and convert between dialogs and LLM chat history.

This module defines the in-memory objects: Message, Dialog, and Attachment. Later modules handle .ipynb files and chat history conversion.

from fastcore.test import *
from fastcore.nbio import mk_display, mk_error

Message types

A message has one of four types:

  • note contains Markdown.
  • code contains executable source and its Jupyter outputs.
  • prompt contains a user’s request and the AI’s response.
  • raw contains untyped text.

The file writer maps these types to notebook cells.

Identity

Messages and attachments have string ids. A dialog uses its name as its identifier. An object compares equal to another instance with the same identifier, or to the identifier itself. For example, you can check msg in dlg.messages or remove an attachment with atts.remove('img1.png').

add_id_hash supplies this behavior for a class. It defines __eq__ and __hash__ using one identifier attribute. Sets and dictionary keys use that same identity.

A Message pairs a request with the answer from its addressee. For a prompt, those are the user’s request and the AI’s reply. For code, they are the source and the interpreter’s outputs. Both kinds of answer belong in output.

Notes address everyone who reads the dialog. Raw messages have no addressee. The index page explains this conversation model in more detail.

The stored fields correspond to a notebook cell: content for source, output, msg_type, id, attachments, and meta. The prompt type is an extension to the notebook cell types. Unknown metadata survives saving and loading unchanged.

A host can expose selected metadata entries as attributes through meta_attrs. This dictionary maps attribute names to metadata keys. Undeclared entries remain in meta.

New message ids contain four random bytes as hexadecimal text. The constructor converts supplied ids to strings. Hosts add display prefixes themselves, such as Solveit’s DOM _ prefix.

content, output, and msg_type use DepProp descriptors. Assigning content calls clear_inp_cache. Assigning output calls clear_out_cache. Changing the type calls both hooks and clears the output. The base class caches its AI rendering in _ai_rend. Subclasses override the hooks to clear any additional caches.

The dlg attribute refers to the owning dialog.

Message

def Message(
    content:str='', # The message text: markdown, code, or a prompt's request
    dlg:NoneType=None, # The `Dialog` this message belongs to
    output:str='', # Jupyter-style output list (code and prompt messages), or ''
    id:NoneType=None, # Message id; 4 random hex bytes if None
    msg_type:str='code', # One of `smsg_types`: code, note, prompt, or raw
    attachments:NoneType=None, # `Attachment`s carried by the message
    meta:NoneType=None, # Remaining cell metadata, carried verbatim through save/load
    **xtras
):

An ipynb cell, or Solveit message (which adds the prompt type)

Factories use Dialog.msg_cls to choose the message class. Set it on a Dialog subclass to create your own Message subclass through inherited factory methods. read_ipynb(cls=...) also accepts a dialog subclass when loading a file.

The displays below show message content, outputs, and flags.

Assign a reply string to Message.output to convert it with prompt_output. Notebook MIME values accept either strings or lists of lines. ai_res returns one string from either representation for use in chat history.

pm = Message('q', msg_type=sprompt, output='A reply')
test_eq(pm.ai_res, 'A reply')
pm.output = 'Edited reply'
test_eq(pm.output, prompt_output('Edited reply'))
test_eq(pm.ai_res, 'Edited reply')
pm_lines = Message('q', msg_type=sprompt, output=prompt_output(['Line 1\n', 'Line 2']))
test_eq(pm_lines.ai_res, 'Line 1\nLine 2')

Sections

A Markdown heading at the start of a note begins a section. The section ends before the next heading at the same or a higher level.

header_info returns the heading’s (level, text) from the start of the content. It accepts up to three leading spaces, as CommonMark allows. Hosts use this helper for sections, collapsing, and outlines. Message.header_level returns zero unless the message is a note starting with a heading.

section_msgs(ms, head) returns the heading and the messages in its section. Pass the collection to search as ms. For example, a host can exclude skipped messages before finding a section. The function respects that filtered collection rather than using dlg.messages.

test_eq(section_msgs(sd.messages, h2), [h2,b])  # body text under the heading doesn't change its level
test_eq(section_msgs(sd.messages, a), [a])  # a non-heading has no span

Rendering outputs for the AI

render_outputs_ai converts Jupyter outputs to text for the model. It combines streams as a terminal would display them and removes ANSI codes. It prefers Markdown to HTML. Images don’t appear in this text because chat history sends them separately as media parts.

The renderer uses preferred_msg_out, concat_streams, and join_out from fastcore.nbio. Below, Message.render_out caches the result. Hosts can customize individual MIME conversions through Message.ai_renderers.

AI_RENDERERS defines the conversion for each preferred MIME type. It removes ANSI codes from plain text, normalizes LaTeX delimiters, and wraps JavaScript in <script> tags.

render_output_ai handles one output. render_outputs_ai handles a list. Both use preferred_msg_out to select a MIME representation. Pass renderers to override or extend the conversion table for one call. Pass dollars=True for consumers that need dollar-delimited math.

A carriage return overwrites earlier stream text, as it would in a terminal. An error contributes its traceback:

test_eq(render_outputs_ai([{'output_type': 'stream', 'name': 'stdout', 'text': 'Hello\rBye\n'}]), 'Bye\n')  # chkstyle: ignore
test_eq(render_output_ai({'output_type': 'execute_result', 'data': {'text/plain': '"42"'}}), '"42"')
test_eq(render_output_ai({'output_type': 'display_data', 'data': {'text/markdown': '**bold**'}}), '**bold**')
test_eq(render_output_ai({'output_type': 'display_data', 'data': {'text/latex': '$x^2$'}}, renderers={'text/latex': str.upper}), '$X^2$')
test_eq(render_output_ai({'output_type': 'error', 'traceback': ['Error: something broke']}), 'Error: something broke')
test_eq(render_output_ai({'output_type': 'display_data', 'data': {'text/html': '<b>hi</b>', 'text/plain': 'hi'}}), '<b>hi</b>')
assert not render_output_ai({'output_type': 'execute_result', 'data': {'text/plain': ''}})

Models tend to repeat the math delimiters in their context. normalize_text_latex gives text/latex outputs consistent delimiters. It accepts bare TeX and the usual inline and display wrappers. By default, the result uses \(...\) for inline math and \[...\] for display math:

def _tl(s, expected, dollars=False): test_eq(normalize_text_latex(s, dollars=dollars), expected)
_tl(r'\(x + y\)', r'\(x + y\)')
_tl(r'$$x + y$$', r'\[x + y\]')
_tl(r'$x + y$', r'\(x + y\)')
_tl(r'x^2 + y^2', r'\(x^2 + y^2\)')
_tl(r'$$\begin{align}x &= 1\\y &= 2\end{align}$$', r'\[\begin{align}x &= 1\\y &= 2\end{align}\]')
_tl(r'\text{Price is: \$5.00}', r'\(\text{Price is: \$5.00}\)')
_tl(r'\begin{align}E = mc^2\end{align}', r'\[\begin{align}E = mc^2\end{align}\]')

For apps whose users write dollar-delimited math, pass dollars=True. Escaped dollars inside the expression remain unchanged. The output rendering functions accept both dollars and renderers:

_tl(r'\(x + y\)', r'$x + y$', dollars=True)
_tl(r'\[x + y\]', r'$$x + y$$', dollars=True)
_tl(r'$x + y$', r'$x + y$', dollars=True)
_tl(r'\begin{align}E = mc^2\end{align}', r'$$\begin{align}E = mc^2\end{align}$$', dollars=True)
_tl(r'\text{Price is: \$5.00}', r'$\text{Price is: \$5.00}$', dollars=True)
test_eq(render_output_ai({'output_type': 'display_data', 'data': {'text/latex': '$x^2$'}}), r'\(x^2\)')
test_eq(render_output_ai({'output_type': 'display_data', 'data': {'text/latex': ['$x^', '2$']}}), r'\(x^2\)')
test_eq(render_output_ai({'output_type': 'display_data', 'data': {'text/latex': r'\(x^2\)'}}, dollars=True), '$x^2$')
test_eq(render_outputs_ai([{'output_type': 'display_data', 'data': {'text/latex': '$$x$$'}}], dollars=True), '$$x$$')

The default text/plain renderer joins lists of lines from notebook files and removes ANSI codes. A per-call renderers entry replaces that conversion:

def _res(data): return {'output_type': 'execute_result', 'data': data}
test_eq(render_output_ai(_res({'text/plain': ['\x1b[31mred\x1b[0m']})), 'red')
test_eq(render_output_ai(_res({'text/plain': '\x1b[31mred\x1b[0m'})), 'red')
test_eq(render_output_ai(_res({'text/plain': ['42']}), renderers={'text/plain': lambda d: f'<{d}>'}), "<['42']>")
outs = [{'output_type': 'stream', 'name': 'stdout', 'text': 'a\n'}, {'output_type': 'stream', 'name': 'stdout', 'text': 'b\n'}, _res({'text/plain': ['42']})]
render_outputs_ai(outs)
'a\nb\n\n42'

render_md converts output lists to Markdown for documents such as dlg2md exports. Consecutive text outputs share an output code fence. Markdown and LaTeX appear directly in the document. Raster images use data-URI links. SVG uses a raw HTML fence instead.

HTML uses a Pandoc {=html} raw fence. Use a Pandoc-compatible processor for this format. GFM renderers display the fence as a code block. HTML takes precedence by default because it usually contains the richest representation. Pass html1st=False to prefer Markdown.

Running a dialog

Dialog.execute runs code messages in an execnb CaptureShell. It stores the resulting notebook-format outputs on each message in memory. Call save explicitly to write them to disk, as with other session operations.

Dialog.select_msgs chooses what to run. It uses fastcore.nbio.select_cells for ids, unique prefixes, and above and below anchors. It then keeps only messages whose msg_type is code. Prompts never execute, even though they serialize as code cells.

For messages other than explicit id selections, the cell’s eval directive determines participation. Without that directive, selection uses the notebook’s setting, then default_eval. Pass ignore_eval=True to skip this filtering. Explicitly selected code messages run regardless of eval.

d.execute(m.id, above=True) runs the selected code through m, inclusive. With no arguments, d.execute() runs all participating code messages, like Solveit’s run-all.

The returned RunResult contains the messages that ran and displays their status. You can look up messages by id.

Long reports collapse successful lines into counted markers. The report keeps the lines nearest the selection anchor: the last lines for an above run, or the first for a below run. Failures always appear with their exception name and value. The final line counts successes and failures, as %nbrun does.

Markdown documents

dlg2md converts a dialog to a Markdown document. Notes contribute their Markdown unchanged. Code appears in python fences, followed by outputs from this module’s render_md inside ::: output divs. Prompts and replies use ::: prompt and ::: reply divs. fmt_tools formats tool wire blocks in replies.

These div class names and the python language label are fixed parts of the format. Viewers use the exact spellings for styling.

For document filling, exportfilter selects which messages contribute. weave uses code outputs in place of code messages. The examples below show both options.

Attachment references in notes become data URIs containing the attached data. The exported document no longer needs a notebook to resolve those attachment: references. For separate image files, such as in a README, use mdhtml.md2gfm with imgdir:

da = Dialog(name='att')
ma = da.mk_message('A ![plot](attachment:img1.png) here.', msg_type=snote)
ma.mk_attachment(tiny_png, 'image/png', 'img1.png')
test_eq(dlg2md(da), f'A ![plot](data:image/png;base64,{base64.b64encode(tiny_png).decode()}) here.\n')

Use exportfilter=True when exporting selected document content rather than the whole transcript. If any message has an export directive, export_filter selects all exported messages, including pinned ones. Otherwise it selects all non-pinned messages. Adding the first export directive switches between those rules.

For a filled document, weave=True turns code outputs into ordinary document text through render_text. This is the plain text from the notebook’s output area. The code source and ::: output wrapper do not appear. A code message without outputs contributes nothing. Other message types keep their usual rendering:

    Message('setup()')])
