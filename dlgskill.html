dlgskill

Read, search, and edit notebook and dialog content through aidialog’s Dialog and Message APIs. Use for cell sources, stored outputs, prompt/reply pairs, and structural message operations.

Workflow. Start with summary_dlg unless reading the full dialog, then find_msgs or view_dlg(incl_out=True) for code, prose, and outputs. Before editing, read nbdev.skill and exhash.skill; for cross-notebook searches, read rgapi.skill (nbrg).

Use message operations for dialogs and fastcore.nbio.Notebook/NbCell operations for plain notebooks. Diagnose with validate_nb, validate_cell, or read_nb. Raw text is only for unparseable files. Propose missing structural operations; never splice notebook JSON.

View fresh lnhashview_msg/lnhashview_cell addresses before hash-verified edits. Use plain msg_* editors where exhash cannot express the operation. Use structural find_msgs predicates for Python symbols/ASTs. Read neighboring prose, including with ids=.

Call documented APIs without speculative fallbacks. Display results bare, never slice or reformat their reprs. Review returned diffs and call dlg.validate().

Files and held objects. File functions take dlg=path, defaulting to set_dlg(path). Each call rereads; edits save automatically. Methods edit held objects until dlg.save(). Save before switching to file functions; reopen before resuming methods. Drop address arguments: msg_str_replace(id, ..., dlg=p) becomes m.str_replace(...). Use d.mk_message/d.remove_msgs in memory. Dialog(msgs) wraps a message list; m.dlg retains ownership.

Views and identity. Summaries use id:t[directives]:content: c=code, n=note, p=prompt, r=raw. Replies follow >; truncations end with a bracketed missing-character count. Directives are nbdev metadata, as in nbio summaries. XML uses item2xml, <out> replies, and directive attributes such as bare export.

File searches return MsgRows/MsgRow snapshots (id, msg_type, content, out, meta); method searches return live FoundMsgs. Index by exact id or unique prefix, never position. Context rows use - instead of the first :. Default context is one neighbor each side, including with ids=; headers_only defaults to zero.

Placement and metadata. The host calls set_cur_msg; writes never move it. Unanchored adds follow it, or append if unset/missing. Chain explicit after= anchors for successive additions.

m.exported and only_exp include source and metadata directives; assignable m.meta_exported uses metadata only. Message.update/update_msg replace attributes, including whole meta; mergemeta deep-merges, with None deleting keys. export=True adds and False removes, migrating source export to metadata without a negative directive. Diffs show XML and meta:. Text editors’ out=True edits prompt replies only; assign other outputs through m.output.

Kernel execution. %nbrun runs in the current kernel. Dialog.execute/Message.execute capture outputs on held messages and return RunResult (abbreviated successes, exceptions on failure). They block; use asyncio.to_thread in async hosts. Read Dialog.execute for selection, shell lifetime, and saving.

%%add_msg [dlg] [msg_type] [export] [before=<id>|after=<id>] takes an unquoted body, trimming trailing newlines. Keywords override bare tokens.

%nbrun [IDS/FLAGS] [fname=PATH] accepts above, below, all, exported, ignore_eval, continue_on_error, and show. fname overrides set_dlg; no selection runs all participating code cells. Only explicit ids display outputs unless show. Errors always name the cell; the final nbrun: N cells ok includes any failure count. Execution uses the kernel’s namespace and standard output/error handling. The magic returns a coroutine for the host to await.

set_dlg

def set_dlg(
    fname, # ipynb path that later calls will default to
    cls:NoneType=None, # `Dialog` subclass to read with from now on (None: keep current; initially `Dialog`)
):

Set the current dialog file, used by these functions when dlg is None

A host calls set_dlg to set the current file and set_cur_msg to set the current message within it. Solveit sets the message when running it. An add_msg call without explicit placement then inserts after the prompt receiving the answer. Writes never move the current message. Calling set_dlg clears it because message ids belong to a file. An unset or deleted current message makes add_msg append instead.

Pass cls to set_dlg to choose the Dialog subclass for subsequent file reads. A host can use this subclass with its own message fields from meta_attrs. The class setting survives later set_dlg calls until you replace it, including when switching files.

set_dlg expands ~ and resolves an absolute path immediately. Changing directories, including with %cd, does not change the current file.

You can read the stored id and path as dlgskill.cur_msgid and dlgskill.cur_dlg_path. Do not import these attributes with from ... import. The setters rebind them, which leaves an imported binding with an old value. For this reason, __all__ does not include them.

Dialog.msg

def msg(
    id, # A `Message` (matched by its id), or an id: exact, or unique prefix
):

The matching Message in this dialog

msg accepts a message object, an exact id, or a unique id prefix. Use the id stored in the notebook. It does not remove host display prefixes such as Solveit’s leading underscore.

The examples use a temporary dialog file. File-based calls will read it again on each call:

tdir = Path(mkdtemp())
d = Dialog(name='demo')
setup = d.mk_message('# Setup', msg_type=snote)
calc = d.mk_message('x = 21\nx*2', msg_type=scode, output=code_output('42'))
ask = d.mk_message('Double it.', msg_type=sprompt, output='It is **42**.')
bad = d.mk_message('1/0', msg_type=scode, output=[dict(output_type='error', ename='E', evalue='boom', traceback=['tb'])])
write_ipynb(d, tdir/'demo.ipynb')
test_eq(d.msg(calc.id), calc)
test_eq(d.msg(calc.id[:5]), calc)  # unique prefixes work too
with expect_fail(KeyError, 'no message'): d.msg('zzzz')

Searching

A search result can include both matches and the messages that explain them. find_msgs includes one neighbor on each side by default, even when filtering by ids.

Index results with a message id or unique prefix that you read from the result. Integer indexing raises an error: position zero could contain context rather than the match you wanted. Missing or ambiguous ids also raise errors.

    header_section:str=None, # Return the section starting with this heading, plus its children

Find this dialog’s messages matching all the given criteria

Dialog.find_msgs returns live messages. Edits through its result change the held dialog. You can search an existing message list by wrapping it in Dialog without changing the messages’ owners.

Search text matches a prompt’s request or reply. An invalid regular expression falls back to literal matching, allowing search text from users to include characters such as *. Pass pred for another criterion, such as a host-specific flag.

Use header_section for a section beginning at a note heading. Use headers_only for an outline. Outline searches default to no context. Other searches default to one message on each side. Pass context=0 for exact matches only:

test_eq(d.find_msgs('42', context=0), [ask])  # matches the reply text
test_eq(d.find_msgs(r'x\*2', msg_type=scode, context=0), [calc])
test_eq(d.find_msgs(only_err=True, context=0), [bad])
test_eq(len(d.find_msgs(r'x\*2')), 3)  # context defaults to 1: the match plus both neighbours
test_eq(d.find_msgs(headers_only=True), [setup])
test_eq(d.find_msgs(header_section='Setup', context=0), list(d.messages))  # everything under the heading
test_eq(Dialog(d.messages[:3]).find_msgs('42', context=0), [ask])  # an ephemeral wrap makes any message list searchable
fm = d.find_msgs('42', context=0)
fm[ask.id].content = 'Double it, please.'
test_eq(ask.content, 'Double it, please.')  # live objects: the edit landed on the dialog
assert ask.dlg is d  # ...and the wrap above didn't steal the message from its real dialog
test_eq(d.find_msgs('*42*', context=0), [ask])  # an invalid regex falls back to a literal match
test_eq(d.find_msgs(pred=lambda m: m.msg_type==sprompt, context=0), [ask])  # host-specific extra criterion
xd = Dialog(name='exports')
exp1 = xd.mk_message('#| export\ndef f(): pass', msg_type=scode)
exp2 = xd.mk_message('def g(): pass', msg_type=scode)
exp2.meta_exported = True
deep = xd.mk_message('## Deep\nbody under the heading', msg_type=snote)
test_eq(xd.find_msgs(only_exp=True, context=0), [exp1, exp2])
test_eq(xd.find_msgs(header_section='Deep', context=0), [deep])  # matched on the first line only
test_eq(xd.find_msgs(header_section='## Deep', context=0), [deep])  # a '#'-prefixed argument pins the level
test_eq(xd.find_msgs(header_section='# Deep', context=0), [])

A query by ids still includes neighboring messages. The integer-indexing error suggests an id from the actual matches:

fm = d.find_msgs(ids=calc.id)
test_eq((fm.matched, len(fm)), ({calc.id}, 3))

def split(
    *linenos:int, # Split before each of these 1-based lines

sm = sd.mk_message('#| export\ndef f(): pass\ndef g(): pass', msg_type=scode, meta={'k': 1})

i2.meta['k'] = 2  # pieces don't share the dict
test_eq(i1.meta, {'k': 1})
sd.merge_msgs(i1, i2)

hd = Dialog(name='hoist')

sd.move_msgs(i1, after=sd.messages[-1])
test_eq([m.content[:4] for m in sd.messages], ['tail', '#| e'])

Editing message text

The text editors use fastcore.tools operations on message content. Set out=True to edit a prompt’s reply Markdown instead. Assignment converts the edited reply back to an output list with prompt_output.

Other message types do not support text edits to outputs. Assign a code message’s output directly. Prompt requests and replies are separate editing targets. The former behavior that joined them for editing is no longer supported.

Pass a list of ids or 'all' for a bulk edit. The result omits unchanged messages and includes errors.

The editors inherit their signatures from fastcore.tools. doc() groups six shared replacement options under replace_params, matching fastcore.editskill:

(tdir/'edit.ipynb').write_bytes((tdir/'demo.ipynb').read_bytes())  # scratch copy: demo.ipynb stays pristine for later sections
with chdir(tdir): set_dlg('edit.ipynb')
test_eq(cur_dlg_path, (tdir/'edit.ipynb').resolve())
test_eq(cur_dlg().msg(calc.id).content, 'x = 21\nx*2')
diff = msg_str_replace(calc.id, 'x = 21', 'x = 40')
assert '-x = 21' in str(diff) and '+x = 40' in str(diff)
test_eq(read_ipynb(tdir/'edit.ipynb').msg(calc.id).content, 'x = 40\nx*2')
diff = msg_str_replace(ask.id, '**42**', '**80**', out=True)
assert '+It is **80**.' in str(diff)
test_eq(read_ipynb(tdir/'edit.ipynb').msg(ask.id).ai_res, 'It is **80**.')
assert str(msg_str_replace(calc.id, "'42'", "'80'", out=True)).startswith('error:')
assert str(msg_del_lines(setup.id, 1, 1, out=True)).startswith('error:')
bulk = msg_str_replace([setup.id, bad.id], '1/0', 'pass')
test_eq(len(bulk), 2)  # bulk mode reports errors alongside diffs
assert 'error' in bulk[0][1] and '+pass' in bulk[1][1]

Structural search

Searching for cfg = misses a binding such as cfg, aux = load(). A broad text search for a short name also finds unrelated text. Use remold’s structural queries through find_msgs(pred=...) for Python symbols and syntax.

symdef_finder finds top-level bindings. These include tuple unpacking, for, with ... as, walrus expressions, imports, and def or class definitions. symref_finder finds references to a name. ast_finder matches an ast-grep pattern.

The name queries return no matches for content that cannot parse as Python. This excludes ordinary prose in the example below:

Working with dialog files

Pass an .ipynb path as dlg to a file function. Leave it as None to use the current file from set_dlg. Each call reads the file again. Mutating calls save their changes.

For a held Dialog, call its methods instead of passing it as dlg. Methods edit in memory until dlg.save(). cur_dlg() reads the current file into a new held object.

Use one approach at a time for each file. Save held edits before using file functions. Reopen the dialog afterward to see file changes in memory. After aidialog has normalized a file, saving an unchanged dialog preserves its serialized bytes. The functions below create, edit, and delete messages directly in files:

%nbrun runs notebook code in the current kernel. Give cell ids or unique prefixes to select cells. The bare flags are above, below, all, exported, ignore_eval, continue_on_error, and show. As with %%add_msg, k=v keywords take precedence over bare tokens. Without a selection, it runs all participating code cells. fname selects a different file for one call.

Explicit id selections run through fastcore.nbio.run_cell with store_history=True. The kernel’s displayhook shows their results. A trailing semicolon suppresses the result through the kernel’s normal handling.

Other selected cells run silently. These include the additional cells selected by above, below, all, and exported. The runner captures their stdout and stderr to keep setup output out of the display. Use show to display every selected cell.

Failures always appear, even in silent runs. Each run ends with nbrun: N cells ok, plus a failure count when needed. The examples below show stopping at an error and continuing past it.

The runner uses the kernel’s namespace and standard streams, display publisher, and error display. It does not need host-specific output handling. The magic returns a coroutine. fastcore.aio.enable_async_magics provides the machinery to await it.
